# DBPanda 开发规范

本文只写**必须遵守**的约定。这些约定是「第一步：地基」建立的，目的是让后面每加一个功能都只改一处。

---

## 1. 新增功能 → 登记命令，不要手写菜单

**唯一入口**：`src/renderer/js/app.js` 的 `registerAppCommands()`。

菜单栏、快捷键、工具栏的可用状态、（后续的）命令面板，全部由 `src/renderer/js/commands.js` 的注册表生成。

```js
{
  id: 'copy-table-name',        // 唯一标识
  label: '复制表名',             // 菜单/命令面板显示的名字
  menu: '编辑',                  // 归属菜单；不填则不进菜单栏
  sepBefore: true,              // 该项之前插一条分隔线
  accel: 'Ctrl+Shift+C',        // 快捷键
  scope: 'notInInput',          // 'global' | 'notInInput' | 'notInEditor'
  bind: true,                   // false = 由浏览器/CodeMirror 自己处理，只显示提示不做全局绑定
  enabled: () => state.open.size > 0,   // 决定菜单/工具栏灰不灰
  run: async ({ target, needConn }) => { /* ... */ },
}
```

### 必须知道的三条

1. **`accel` 是唯一事实来源。** 菜单上的快捷键提示和实际生效的按键都来自它，不可能再对不上。
   不要在别处再写一遍键位。

2. **`enabled()` 只管「灰不灰」，不管快捷键。** 快捷键照样触发，由 `run()` 自己给出
   「请先打开一个连接」之类的提示——比按了没反应更容易理解。

3. **CodeMirror 或浏览器已经处理的键，`bind` 必须设 `false`。**
   例如 `Ctrl+Z`、编辑器内的 `Ctrl+F`。否则会和 `工具 → 在库中查找` 抢同一个键。

### 键位方案

`src/renderer/js/keymaps.js` 里是各套方案（默认 / Navicat 兼容）。方案只是一张覆盖表：

```js
overrides: {
  refresh: { accel: 'F5', scope: 'global' },  // 改键位，顺带放开作用域
  'goto-table': null,                          // 取消这个命令的快捷键
}
```

没写进 `overrides` 的命令自动还原为出厂键位，**来回切换不会残留**。

- **作用域不能用来错开两个命令**：`global`/`notInInput`/`notInEditor` 在焦点位于树或网格时**都会生效**，
  所以同键必冲突。真正错开编辑器内外的机制是 `bind: false`。
- 编辑器（CodeMirror）里要随方案变化的键，用 `CodeMirror.Pass` 放行给全局，
  不要重新绑定——参考 `queryTab.js` 里 F5 的写法，已打开的标签页也会立刻跟着变。
- `accelConflicts()` 会检出抢键的命令，启动时自动跑并打到控制台。

### 验收标准

新增一个功能后，它应当**同时**出现在菜单、快捷键和命令面板里，而你只改了 `registerAppCommands()` 一处。
如果你发现自己在改第二个文件，说明用法不对。

新增键位方案时，`scripts/test-step1.js` 会自动对**每一套方案**校验：无冲突、每个键都能反查回自己的命令、
`overrides` 里没有指向不存在的命令。

## 2. 数据网格是虚拟滚动的，不要假设行都在 DOM 里

`src/renderer/js/grid.js` 只渲染可见区 ± 12 行（超过 150 行时启用）。**给网格加功能前必须知道这几条**：

| 要做的事 | 正确做法 | 错误做法 |
|---|---|---|
| 按行号拿单元格 | `this._tdAt(dr, c)`，**返回值可能是 null** | `tbody.querySelectorAll('tr')[dr]` |
| 让某一行可见 | `this._scrollRowIntoView(dr)` 再取 DOM | 直接 `scrollIntoView` |
| 遍历行改样式 | `tbody.querySelectorAll('tr[data-dr]')` | `tbody.querySelectorAll('tr')`（会选中占位行） |
| 行的真实序号 | `tr.dataset.dr` | DOM 里的位置 |

- **`data-dr` 是显示行序号**（含新增行），DOM 位置不等于行号。
- 行高由 CSS 变量 `--grid-row-height` 决定，虚拟化按**实测行高**算窗口。改行高相关样式后，
  已打开的网格要调 `refreshAllGrids()` 重排。
- 行数 ≤ 150 时退化为整表渲染，行为与虚拟化前完全一致。
- 任何「只对可见行生效」的实现都是 bug：选中、编辑、复制都必须基于**数据模型**，
  DOM 只是模型的投影。离屏行上调 `_setCell` 是合法的（td 传 null 即可）。

冻结列、隐藏列、内联筛选行、选区统计等后续功能，全部要按这套约束来写。
`scripts/` 没有覆盖网格——它的回归断言在 **smoke** 里（`[SMOKE][grid]`），改 grid.js 后务必确认它是绿的。

## 3. 用户可见文案一律走 `t()`

```js
import { t } from './i18n.js';

el('button', {}, t('保存'))
toast.info(t('共 {n} 行', { n: 12 }))
```

`t()` 目前**原样返回中文，不做任何翻译**。它存在的意义是：接入多语言时只需挂上词典，
不必再逐个文件抠字面量。

- **新代码**：界面文案必须走 `t()`。样板见 `src/renderer/js/settingsDialog.js`。
- **存量代码**：暂不改造。后面还会新增大量界面，边改边加等于翻两遍；
  存量抽取会安排一个专门的时间窗口统一做。
- **不需要 `t()` 的**：日志、异常堆栈、SQL 关键字、通道名等非界面文本。

## 4. 用户偏好一律进设置中心

**不要再用 `localStorage`**，也不要在功能模块里自己找地方存。

- 主进程：`src/main/settings.js` 的 `SCHEMA` 里加一行（键、默认值、取值校验）。
- 渲染进程：`getSetting(key)` 读，`updateSettings({ key: value })` 写，
  `onSettingsChange(cb)` 订阅变更。
- 界面：在 `src/renderer/js/settingsDialog.js` 里加一组。

### 两条硬性要求

1. **默认值必须与现有表现一致。**
   例如 `sidebarWidth` 的默认值必须等于 `css/app.css` 里 `#sidebar` 的 `width`，
   否则老用户升级后布局会被静默改掉。`scripts/test-step1.js` 里有断言守着这一条。

2. **渲染进程传来的值一律不可信。**
   `SCHEMA` 之外的键直接丢弃，非法值回落默认值，绝不把渲染进程给的对象原样落盘。

## 5. 涉及数据库的操作会被自动审计

`src/main/ipc.js` 里有两个统一入口，所有操作都从这里穿过去，审计日志已经埋在这两处：

- `h(channel, fn, approvalOperation)` —— 绝大多数处理器
- `dbaHandler(fn, approvalOperation, channel)` —— 需要推送进度的 DBA 工具

**新增 IPC 处理器请优先用这两个包装器**，这样它天生就被记录，不需要单独埋点。
确实要用裸 `ipcMain.handle` 时（例如需要 `event.sender` 推流），必须自己补
`auditLog.record({ channel, payload, approvalOperation, ms, ok, error })`，
可参考 `conn:save` 和 `import:run`。

### 只读连接

`safety.assertNotReadOnly(operation, payload)` 在 `consume()` 和 `issue()` 里各调一次，
**所有受保护操作都会先过它**。新增写类操作时，把操作名加进 `READ_ONLY_BLOCKED` 即可。

- 只读 = **不修改数据库**。导出到本地文件（`db.exportTable` / `dba.dump`）只读库，因此允许。
- 自由 SQL 用既有的 `isExplicitlyReadOnly()` 判定，它足够保守（MySQL 可执行注释、
  `SELECT INTO`、`FOR UPDATE`、未知函数调用一律不算只读）。**不要另写一套宽松的判定。**
- 目标端才拦：`dba.transfer` 只看 `dstConnId`，源库只读不影响传出。

### 影响范围预检

`impact.js` 把 UPDATE/DELETE 改写成 `SELECT COUNT(*)`。唯一的设计底线：

> **能保证等价改写的才给数字，其余一律返回「无法预估」+ 原因。**
> 一个错的行数比没有行数危险得多。

多表、CTE、`RETURNING`/`OUTPUT`、`LIMIT`/`TOP` 全部拒绝改写。
定位关键字用**等长掩码**（注释变空格、字符串内容变 x），切片用原文下标——
直接对原文做正则会匹配到字面量里的 `where`/`join`，把注释拼进生成的 SQL 还会
把后面的 WHERE 整个注释掉。

### 备份与定时任务

- **备份目录由主进程决定**（`userData/backups`），渲染进程指定不了路径。这不是疏忽——
  让渲染进程决定主进程往哪写文件，等于开了一个任意写入的口子。代价是目录暂不可配置。
- 备份完成后必须**完整解压校验一遍**。不做这步，磁盘写满或进程被杀会留下一个
  看着正常、实际截断的备份，而它的价值恰恰在于出事那天能用。
- 还原是 `backup.restore` 审批操作：会 DROP 现有表重建，因此**生产库要审批、只读连接直接拒绝**。
- 定时任务**只在应用运行时生效**。界面上必须写明，否则用户会以为关掉软件也在自动备份——
  那比没有这个功能更糟。

### 长任务一律登记到任务中心

新增耗时操作时，用 `taskCenter.startTask()` 登记，并在进度回调里 `task.progress()`。
对话框自己的进度条照旧——任务中心是**额外**的一份登记，不接管执行。
不登记的话，用户一关对话框就再也看不到这个任务了，而它在主进程还在跑。

### 绝对不能进日志的内容

密码、SSH 私钥口令、AI API Key。`auditLog.js` 按键名做了兜底裁剪（命中即替换为 `[已隐去]`），
但**不要依赖兜底**——新增字段时自己确认一遍。`scripts/test-step1.js` 里有断言守着这一条。

日志位置：`%APPDATA%/DBPanda/audit.log`，5 MB 滚动，保留 3 个文件。查看界面在后续版本提供。

## 6. 提交前跑一遍

```bash
npm run verify
```

依次执行：品牌资源校验 → 对话框布局 → 工作区恢复 → **基础设施自检** → 数据库层自检 → 界面冒烟。

其中 `npm run core:test`（`scripts/test-step1.js`）专门守住本文这几条约定，改动
命令注册表 / 设置中心 / 审计日志时务必确认它是绿的。
